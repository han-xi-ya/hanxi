# HubKit 项目规范与 Claude Code 指令

## 📌 核心原则与提交规范

### 1. Git 提交规则
- **中文提交信息**：所有 Git commit message 必须使用清晰、规范的**中文**编写。
- **提交信息格式**：遵循 Angular / Conventional Commits 规范，即 `<type>(<scope>): <中文描述>`。
  - `feat`: 新增功能 / 模块
  - `fix`: 修复 Bug / 问题
  - `perf`: 性能优化
  - `refactor`: 代码重构（不影响功能的结构调整）
  - `docs`: 文档变更
  - `style`: 代码格式调整（不影响业务逻辑）
  - `test`: 测试用例新增或修改
  - `chore`: 构建配置、依赖维护、辅助工具等杂项变更
- **示例**：
  - `feat(frpc): 新增连接状态实时嗅探与断线重试机制`
  - `fix(portscan): 修复并发端口扫描时的上下文超时泄露问题`
  - `perf(frontend): 优化日志流前端虚拟列表渲染性能`
  - `chore(deps): 升级 Wails v3 绑定依赖库`

### 2. 合理原子化提交
- **单一职责（Atomic Commits）**：一个提交只做一件事，严禁将不相关的多项变更（如同时修改前端样式、后端逻辑、更新文档）揉成一个巨型提交。
- **保持编译通过**：每个提交必须保证代码结构完整，前后端均可正常编译与运行。
- **排除无关文件**：禁止提交编译产物（如 `bin/` 产物、临时文件、测试日志、操作系统生成的隐藏文件等）。

### 3. 操作与安全守则
- **不自动 Commit/Push**：除非用户明确要求提交或推送，否则不擅自执行 `git commit` 或 `git push`。
- **展示变更摘要**：在用户要求提交前，先简要展示即将提交的文件清单与改动摘要。
- **敏感操作确认**：删除文件、覆盖核心模块、修改配置/密钥相关逻辑前，必须明确提示与确认。

## 🛠️ 技术栈与架构参考
- **后端**：Go 1.24+、Wails v3.0-beta
- **前端**：Vue 3 + TypeScript + Vite + Tailwind CSS / Element Plus
- **平台特性**：Windows JobObject 隔离、Windows DPAPI 硬件级加密、Windows 原生提权与托盘
