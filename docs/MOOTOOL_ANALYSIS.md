# MooTool 借鉴分析（简版）

> 对象：[rememberber/MooTool](https://github.com/rememberber/MooTool)——一个 Java 写的桌面开发者工具箱，20 多个小工具内置自研（JSON 格式化、时间戳、编解码、二维码、取色、正则……），最新版还把工具开放给 AI 客户端调用。
> 和 hanxi 的关系：同一类产品的另一种路线——它全部自己做，hanxi 主要托管别人的工具。
> 详细版（含源码坐标、逐项论证）见 git 历史 `77044c0`。

## 结论

值得学的**机制**有三件，**功能**要补一块，其余是零碎借鉴，还有六件事明确不学。

## 最值得学的三件事

### 1. 把 hanxi 开放给 AI 调用（MCP 接入）

MooTool 新版让 Claude Code、Codex、Cursor 等 AI 客户端能把它的工具当命令调用。但它开放的都是些 AI 本来就会的小工具，意义不大；**hanxi 手里的牌反而硬得多**：everything 全盘秒搜、OCR 识图、envcheck 环境体检、memo 搜索、托盘条目启动——这些是 AI 自己拿不到的本机能力。

hanxi 落地很简单：给 exe 加一个 `hanxi mcp` 无界面子命令即可，Go 单二进制天然支持。注意两点：写 AI 客户端配置文件要默认关闭、改前备份；portkill 这类提权操作**永远不开放**给 AI。

### 2. 统一的「历史记录」

MooTool 每个工具的结果都自动存进一个统一的历史库（每类上限 200 条，可搜索、可一键回填、可复制），前端是一个通用面板，各工具一行代码接入。

hanxi 的 OCR 结果、端口查杀记录、扫描报告现在都是**用完即抛**的。建一个公共的 `internal/history` 存储 + 通用历史面板，各模块共用——这也正好给项目自认的最大债务（公共包没下沉、同段代码拷 14 份）立个"新功能从第一天就走公共包"的样板。

### 3. 数据自动做版本快照

MooTool 的随手记是"一个文件夹就是一个库"，并且会在你**离开编辑器或切走窗口时自动 git commit 一次**——手滑删错内容随时能回滚，全程无感。它调的是系统 git，不是内嵌 git 库。

hanxi 的 memo、配置目录本来就是纯文件，天然适合这套玩法：memo 改成每条一个文件 + 空闲时静默快照。git 不存在就降级为普通备份。

## 要补的功能：开发者小工具

hanxi 的「开发者工具」分组里全是托管的外部软件，**一个自研小工具都没有**，而这恰恰是工具箱类产品的日活来源。MooTool 证明了这类工具纯 Go 写起来很便宜。建议打包成一个 `devkit` 模块（内部分子标签页），第一批：

> JSON 格式化/转换、Base64/URL 编解码、加解密（含国密）、时间戳、正则测试、Cron 表达式、**快捷替换面板**（驼峰↔下划线、按行去重排序等 27 种批量行操作）、二维码生成识别。

第二批再考虑：屏幕取色、文本对比、HTTP 客户端（支持 cURL 导入）、Hosts 管理（hanxi 有现成提权基建，比别家工具改 hosts 更顺）。

## 零碎可学

- **剪贴板惯例**：每个工具标配"从剪贴板粘贴/复制结果"按钮，但**不做全局剪贴板监听**（MooTool 刻意如此，保隐私）。
- **本体自更新**：一份带 sha512 校验的更新清单 JSON，启动时检查一次给托盘提示；MooTool 没做签名，hanxi 要做（发布私钥签 manifest）。
- 小细节：长任务时自动阻止显示器睡眠（引用计数式）、托盘直接挂"取色/识码"这类高频动作、主题强调色一键切换。

## 值得学习的功能总表

一张表列全，按落点归类：

### A. 机制类（跨模块公共能力）

| 功能 | 它是什么样 | hanxi 落点 | 优先级 |
|---|---|---|---|
| MCP / Skill AI 接入 | 应用工具以 stdio 协议开放给 Claude Code / Codex / Cursor 调用，含一键安装、只读授权、可撤销 | `hanxi mcp` 无界面子命令 | P0 |
| 统一历史记录 | 所有工具的输入/输出自动入库（每类 200 条），通用面板可搜索/回填/复制/清空 | `internal/history` 公共包 + 通用 Vue 面板 | P0 |
| 数据自动版本快照 | 空闲或窗口失焦时静默 git commit 一次随手记库，删错随时回滚 | memo 文件库化 + 配置目录快照 | P1 |
| 轮询自适应（"懒启动"残余项） | 页面离开时模块后台轮询自动降频（5s→60s），回来恢复 | flclash 等轮询重模块单独小改 | P3 |
| 本体自更新 | 更新清单 JSON：每平台每包型带 sha512，按平台选包、校验后提示安装 | hanxi 自身升级通道（加签名） | P2 |
| 剪贴板联动惯例 | 每个工具标配"从剪贴板粘贴/复制结果"，不做全局监听 | 写进前端设计规范 | P2 |

> **懒启动不用做（核源后修正）**：MooTool 的页面级懒加载 hanxi 早已具备且更完整——`registry.EnsureActive` 按"进路由/调接口/托盘命令"三入口懒初始化，停用即 `OnDestroy` + GC 主动归还内存（`internal/extapi/registry.go`），仅 wechat/quickmenu 因全局钩子与网关语义在启动时显式激活。真正残余的只有：轮询重模块的降频小改（上表 P3）+ 一条架构约定（`OnInit` 内禁同步外部进程/网络 IO，防"首次进入卡页面"）。

## 明确不学

1. 七条产品线重写（Electron/Tauri/Flutter…）——个人炫技，hanxi 锁 Go+Wails 单栈。
2. 自带 Tesseract OCR——我们有效果更好的私发 hanxi-ocr，不倒退。
3. 翻译+单词本——依赖免费端点随时失联，不做。
4. 全局剪贴板监听——隐私问题，学它的手动粘贴模式。
5. PDF 拆合、图片加水印——已有 piclite/snipaste 托管，重复建设。
6. 抄它的自更新实现细节——清单格式可参考，但无签名这点不行。
7. 闲置模块自动停用——MooTool 能一刀切是因为它没有常驻型模块；hanxi 的 quickmenu 钩子、wechat 网关、frpc 实例、ddnsgo 控制台都是"页面关了事没完"，自动停会误伤（懒加载本身已有，见 A 表注）。

## 建议动手顺序

| 顺序 | 事项 | 量级 |
|---|---|---|
| 1 | 统一历史记录公共包，先接 OCR/portkill/envcheck 三个模块 | 小 |
| 2 | `hanxi mcp` 子命令，只开放检索/识别类只读工具 | 中 |
| 3 | devkit 第一批小工具（全部顺手接历史） | 中 |
| 4 | memo 文件库化 + 空闲自动快照 | 中 |
| 5 | 本体自更新、取色器、HTTP 客户端等 | 按需 |
