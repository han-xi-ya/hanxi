## 2. 绑定指针：载体与格式（卡片遗留问题定稿）

- **载体**：exe 同级普通文件 `hanxi.bind`。硬要求"指针存放处不能依赖被绑定目录"
  ——同级文件天然满足：绑定动作本身只发生在 exe 可写的场合，且随应用目录整体
  拷贝即带走声明（"拔了就走"的便携正统性）。
- **格式**：首个非空行 = 数据目录绝对路径（Windows 口径必须带盘符），LF 结尾，
  UTF-8；解析容忍 BOM、`\r\n`、行首尾空白；后续行忽略。记事本可直接手工编辑，
  无需任何专用 UI 也能救砖。
- **语义**：文件不存在或内容全空白 = 无声明（走同级）；有内容但非绝对路径 =
  无效声明 → fail loud（有声明必兑现，无静默）。空文件即手工解绑通道。
- **为何不用注册 HKCU 或环境变量当载体**：注册表破坏"整个文件夹拷走即全带走"
  的便携语义且是隐形第二真相源（与 hanxi.bind 打架时无法仲裁）；环境变量对
  双击启动的桌面用户不可达。两者都被"用户说了算、无静默路径"原则否决。
  代价如实宣告：**exe 目录只读时绑定不可用**——此时唯一处置就是搬家，
  fail loud 指引与同级强制 dogma 同构（见 §4 MSIX）。
- **换绑/重定位策略**：只改声明，**不自动搬运数据**（自动搬 = 半路断电数据撕裂，
  且"搬家"是低频重决策，让用户自己动手 + UI 明示）。重启后生效：路径快照在
  InitPaths 一次解析，运行中不改家。设置页提供「更改位置…」（输绝对路径 →
  校验+预创建目标+写指针）与已绑定态的「回到同级」（删指针，幂等）。

## 3. 存量迁移（卡片硬问题②定稿）

首启在解析成功、派生目录创建**之前**检查一次：

- **闸门**（四条全过才搬）：`%APPDATA%\Hanxi` 可定位；旧家 ≠ 新家（Windows
  大小写不敏感口径）；新家不在旧家之内（exe 恰住 %APPDATA%\Hanxi 下时放弃自动搬）；
  旧家携数据根特征（config.json 或 versions/）且新家尚未安身（防降级回滚反向污染）。
- **语义**：move——`os.Rename` 逐顶层条目直通；跨卷（旧家在 C 盘、新家在外置卷）
  退化为整棵子树复制，**复制全部成功后才删源**；任何一步失败旧家原样保留，
  绝不先删（DoD："搬迁成功前不删旧家"）。
- **新家同名条目跳过不覆盖**（新家优先，与 state_migrate.go 的既有纪律同谱）。
- 全部搬光且无跳过时顺带删除空旧家目录，完成"退出用户目录"最后一米；
  残留任何条目/失败项则保留原地，日志留痕，不阻断启动。
- 旧 `data/` 按裁定③**不搬**（最迟 v0.4 用户手工迁移，首启 WARN 指路）。

## 4. MSIX 裁决状态（DoD⑤，留给用户的产品裁决）

MSIX 包形态 exe 住 `Program Files\WindowsApps`，同级根本不可写——本改造后
该形态启动即触发 fail loud 弹窗（引导搬家/绑定），**不静默**，符合 DoD⑤
"按产品裁决处理不静默"的底线；但"就此放弃 MSIX 形态还是保留为例外形态"
仍是卡片明言留给用户的产品裁决，未在本次工程内代为拍板。当前发布口径
（NSIS/zip/单文件 exe 矩阵，DEVPLAN §2.5）不受影响。
