`buttonColorContract.spec.ts` 对本模块的硬约束（实读该 spec，a/b/e 三则 + c 则锁 tokens）：

- 按钮族规则里**零裸 hex/rgb() 字面、零 `*-glow` 引用**——豁免须显式登记，新页默认无豁免资格；

## 1. 模块定位与信息架构

**一句话主任务**：管一份"跟人走的 SSH 机器账本"——账本随 hanxi 数据目录经 NAS 同步可搬家，**钥匙（私钥文件）不跟账本走**；界面的职责就是把"账本、本机钥匙、已导出给 ssh 的那份文件"三者之间的对账关系摆在明面上，并提供每行的两个动作（测连通、部署公钥）。

不是"SSH 客户端"：本模块不发起登录会话、不嵌终端、不管理 known_hosts（刻意不做见 §10）。

```
┌ PageHeader「SSH 主机清单」 ────────────── [导出配置 .btn-primary] [新增主机 .btn-secondary] ┐
│ subtitle：账本同步走、钥匙不走；这里管的就是两者的对账。（窄窗先丢这句）                     │
├ ① 导出对账带（常驻，页面级状态；UiBanner 或 chip 行） ────────────────────────────────────┤
│   ● 状态一句话 + 真实目标路径(mono) + 待导出摘要(±行数)          [导出]/[重新导出]         │
├ ② 主机列表（.section-card > .table-container > .tbl；≤760px 转行卡） ─────────────────────┤
│   [启用✓] 别名(mono,strong) │ 地址:端口(mono) │ 用户(mono) │ 密钥(present/⚠缺失) │ 备注 │ 动作 │
│   ▸ 行内展开条（测连通结果 / 部署结果 / 密钥缺失指引，三选一，同 .check-verdict 形制）      │
├ ③ 编辑模态（modal-card 家族，新增与编辑同构；≤460px 底部抽屉） ──────────────────────────┤
└ ④ 部署口令模态（独立小卡：一次性口令 + "显示"开关；见 §6） ─────────────────────────────┘
```

分区职责分离（design-system「分离全局状态/主任务/受管资源/辅助元数据」）：① 是**全局态**（跨行的账本↔导出关系），② 是**受管资源**，③④ 是**任务面**。导出动作放页头而不放列表内部，因为"导出"作用于整个账本而非单行。

| 区 | 初始/加载 | 成功 | 空 | 错误 | 降级/陈旧 |

| ① 导出对账带 | 骨架短句「正在核对账本与导出文件…」+ spinner 仅请求期 | 「已导出，与账本一致 · 最近 2026-10-22 14:03」 | 账本无行：带不显示，由列表空态承载（不双空态） | 读取/导出失败：`banner-error` 点名失败动作 + 原因 + [重试] | 文件被外部改动 / `~/.ssh/config` 缺 Include：`chip-warning` 如实标异常态，不降 opacity（stale 禁靠变淡，checklist 在案） |

| ④ 部署模态 | 执行中：按钮保宽转「部署中…」+ `.live-pulse` | 结果进列表行展开条，模态关闭（口令已销毁） | — | 失败四态文案见 §6.5，落模态结果位或行展开条 | 口令只活在本模态实例，任何出口（成功/失败/取消/Esc/遮罩）立即清空字段值 |

### 3.2 密钥缺失的醒目呈现（本模块设计要点）

**场景账**：整目录随 NAS 同步 → 换机后必然出现"有账本没钥匙"。三态判据（后端逐行返回，UI 不自己 stat——§12 契约项）：

| keyStatus | 呈现 | 配色档位（全部走全局原子，无 scoped 彩底） |
|---|---|---|
| `present` | 路径原文，无徽标（**正常不添噪**） | — |
| `missing` | `⚠ 缺钥匙` `UiStatusChip tone=warning`（`chip-warning`）+ 路径加删除线样式？**否**——不加私造样式，路径正常显示 | 图标+文字双通道，不只靠色（checklist） |
| `unknown`（读不了目录） | 「无法判定」`chip-neutral` + title 原因 | — |

点击 `缺钥匙` 徽标或行展开自动条给**完整叙事文案**（说机制、不吓唬）：

> 账本跟着 NAS 走到了这台机器，但私钥 `C:\Users\…\.ssh\id_ed25519` 没跟过来——本机现在找不到它。
> 三选一：① 在本机重新生成一对密钥再向远端部署公钥（点「部署公钥」，缺钥匙时流程会引导）；② 把私钥文件从原机器拷到上面的路径；③ 如果远端本来就靠密码登录，可编辑此行把密钥路径清空。
> 注意：即便文件在，**远端认不认这把钥匙**也要部署过公钥才算数——「测连通」测不出这一点（它只做端口与版本横幅探测，不碰认证）。

最后一段是本模块最容易被用户想错的边界，常驻在指引里而不是藏在 toast。

### 3.3 空态文案（禁"暂无数据"了账）

> **账本还是空的。**
> 在这里登记 SSH 机器：别名就是你以后 `ssh <别名>` 用的名字。保存后点「导出配置」，才会写进本机的 `~/.ssh/hanxi.conf` 让 ssh 真正认得它们。
> 清单数据存在 hanxi 模块配置里、随数据目录同步搬家；**密钥文件不跟着走**，到新的电脑后本页会在"密钥"列指出哪台缺钥匙，跟着提示走即可。
> [新增第一台]（`.btn .btn-primary`，整页唯一主钮位；此处唯一 CTA 恰是合规的——四轮返工定案是"形制不分档"，整页唯一主操作也用蓝洗档，非例外）

### 3.4 删除（destructive 档）

走 `useConfirm`，`tone: 'danger'`，details 列 别名/地址：

> title：删除账本里的 nas01？
> description：只删这条清单记录。**不会动**本机磁盘上的私钥文件，**也不会撤销**已经部署到远端的公钥——远端还进得去的话请在那里删 `~/.ssh/authorized_keys` 里的对应行。下次「导出配置」后，`hanxi.conf` 里这台机器的条目才会一并消失。
> confirmLabel：删除（`.btn-danger`）／cancelLabel：取消（`.btn-secondary`）

## 4. 新增/编辑表单：校验规则与错误文案表

模态（modal-card 家族；≤460px 转底部抽屉，走 ConfirmDialog 先例形制）。字段 `label` 常驻（placeholder 不当标签用），错误文本 `id` 经 `aria-describedby` 绑进字段，出错字段 `aria-invalid="true"`。

**反馈时机**：即时但不出声——字段 `blur` 后校验一次，报错则此后**每次击键实时重评**（红→绿当场消）；`pristine` 未触碰字段不着色；点保存时全字段兜底评一次，首错字段获焦。保存钮不因校验红而禁用（点了要能看见为什么不能存，禁用钮不会解释自己）。

### 4.1 别名字段（ssh 配置注入面，规则 `[a-z0-9_-]{1,32}`，错误文案必须讲"为什么不行"）

每条文案带机制说明——用户被拦时应当学到规则的形状，而不是只收到"格式错误"。文案以中文全角标点、行内示例回显用户原输入（等宽）：

| 情形 | 即时文案（错误文本区，danger 文字色走 `.text-danger` 家族原子） |
|---|---|
| 空 | 「别名必填：它既是 `ssh <别名>` 命令里的名字，也是导出配置里 `Host` 行的匹配名。」 |
| 含大写字母 | 「别名用小写（当前 `Nas01`）。ssh 的 Host 匹配**区分大小写**——`NAS` 和 `nas` 是两条不同别名，账本里并存时人眼分不出，导出的配置也会多出一条你永远打不中的条目。」 |
| 含空格 / 换行 / 制表 | 「别名不能含空白（当前含空格）。导出时它写在 `Host ` 行里，一个空格就会让 ssh 把后半截**当成第二个匹配模式**——等于替你在配置里多开了一扇门。」 |
| 含 `*` `?` | 「`*` 和 `?` 在 Host 行是通配符：写成 `nas*` 会匹配所有 nas 开头的连接，这台专属配置会套到别的机器头上。别名里不能用。」 |
| 含 `@ : / \` ` "` `'` 等其他符号 | 「只允许小写字母、数字、`_`、`-`（当前含 `@`）。`user@host` 这类信息有专门的『用户』『地址』栏；写进别名只会让 Host 名带上 `@`，`ssh <别名>` 根本匹配不上。」 |
| 超过 32 字符 | 「别名最长 32 字符（当前 41）。它是行内列与命令行里天天出现的名字，长了会在窄窗口里断行、在 `ssh ` 后头难以辨认——描述机器的话请写备注。」 |
| 与账本内其他行重名 | 「账本里已有一台 `nas01`。别名是账本主键，也是导出配置的匹配名——重名时后写的那条会覆盖先写的。」（保存前拦，非仅后端拒） |
| 以 `-` 开头（**现规则放行，本方案提请收紧**） | 见 §4.5：现字面规则 `[a-z0-9_-]{1,32}` 允许 `-nas`；这类名字作为命令使用（`ssh -nas`）会被解析成命令行选项。UI 文案：「以 `-` 开头会被命令行当成选项参数（`ssh -nas` 读作"参数 nas"），建议以字母或数字开头」。拍板前按现规则只做**提示级**（warning 文字，不拦保存）。 |

### 4.2 其余字段

| 字段 | 规则 | 即时文案要点 |
|---|---|---|
| 地址 | 必填；只收 IP/域名。协议前缀、内嵌端口、`@` 一律拒 | 后端 `sshTargetAddr` 已有整套具体中文（「主机栏只填 IP 或域名，协议与端口有独立栏（当前为…）」等，含 IPv6 正确支持），**前端只做 blur 级轻校验，最终以后端原文落字段下**——同一套判据两处各写一份是 sshprobe.go 头注点名的反面教材，UI 不造第二判据 |
| 端口 | 1–65535 整数；空=22（placeholder `22`） | 「端口需在 1–65535（当前 `0`）；留空按 22 记」 |
| 用户 | 可空 | 空时字段下常驻 info 文字（非错误）：「留空将以**本机**用户名登录远端。账本随 NAS 同步后，别的电脑本机名不同——建议显式填。」 |
| 密钥路径 | 可空；文本框 + [浏览]（`.btn-secondary`，走后端原生文件选择——§12） | 失焦即查存在性：不存在→ **warning 不拦保存**（"钥匙没到位是搬家后的常态，账要先记上"）：「本机找不到这个文件。登记仍可以；等钥匙到位（拷过来或重新部署）前，该行会一直带「缺钥匙」标。」目录不可达→「无法判定」提示，不判缺 |
| 备注 | 可空，≤100（textarea 单行版 input；粘贴按钮**不加**，剪贴板惯例明令短结构化输入不配按钮、单行备注非富粘贴面） | 超长即时计数文案「备注 108/100，请精简」 |

### 4.3 模态底部动作行

左侧 `.hint-line`：「保存只改账本；要让 ssh 用上它，请再点『导出配置』。」——账本与导出两步制，在表单里就把话说在明面，避免"保存了怎么连不上"。右侧 [取消] `.btn-secondary` + [保存] `.btn-primary`（模态内唯一主钮；两钮同族 `min-height: var(--control-h-lg)`，窄抽屉满宽堆叠走 ConfirmDialog 460 先例）。按钮文字 `white-space:nowrap` 由全局基座兜住，布局让位而非折字（"竖排按钮"教训在案）。

### 4.4 表单不做的即时校验

用户名合法性（远端的事本机不知道，不做规则校验，最多长度软限）、密钥文件"远端是否接受"（banner 探测测不出，§3.2 已声明边界）。

### 4.5 提请机主/后端裁定的规则收紧（不在 UI 私改）

字面规则允许以 `-` 开头/结尾的别名；建议收紧为 `[a-z0-9_][a-z0-9_-]{0,31}`（首字符字母/数字/下划线）。理由如 §4.1 末行。**UI 文档先行按现规则呈现，收紧与否进 §12。**

## 5. 「测连通」：只读横幅探测的四态呈现

### 5.1 语义与边界（绝不把"连上了"和"能登录"混成一个布尔）

复用搬来的 `CheckSSH`：它刻意只做版本横幅交换、不做 KEX 与认证（sshprobe.go 头注），所以这个动作能回答的是"**端口上有没有一个认领自己是 SSH 的服务**"，永远回答不了"这把钥匙/这个密码进不进得去"。UI 文案与状态名一律照此边界写，行内成功态也不许出现"可用/可登录"字样。

⚠ **四态分桶的取证问题（如实提出）**：`SSHCheckResult` 目前只有 `ok bool + error 中文文本`，四态要靠解析 Error 原文分桶——脆。且任务书四态里的"算法协商失败"在 banner 层**原理上不可见**（不走 KEX），它是 `CheckSSHAuth` 的 verdict（sshauth.go `AlgorithmNegotiationError` 分支）。处置：

- 过渡口径：banner 动作呈现三态 + 原文（§5.2 表），**不制造"算法问题"这一空转档位骗人**；
- 终态口径：待后端在结果里加 `outcome` 枚举（§12-1），UI 按枚举映射，文案对表落位；"算法不通"档位属于未来显式的「试钥匙」动作（§12-6），不进「测连通」。

### 5.2 结果呈现（写入该行的展开条，Toast 只做回执不做唯一通道）

容器沿用家族形制（`portscanPanels.css` `.check-verdict` 同源语法：左判定右元信息，窄窗 wrap）。

| 态 | 触发（后端事实） | 呈现 | 档位 |
|---|---|---|---|
| 通 | `ok=true` | `chip-positive`「SSH 可达」 + 地址·耗时(mono) + 版本横幅原文(`.check-server`，overflow-wrap:anywhere) + 常驻 hint：「这只证明端口通且对方认领自己是 SSH；能不能登录不由本动作判定。」 | 绿 chip + 文字，非只色 |
| 不通 | `ok=false`，原因=连不上（拒绝/不可达） | `chip-danger`「连不上」 + Error 原文(`.check-reason`) | danger |
| 端口通但不是 SSH | Error 形如「端口通，但应答不像 SSH（首行 …）」 | `chip-warning`「端口通，不像 SSH」 + 首行摘录 + hint：「可能是端口撞上了别的服务；列表里的端口是否填对也请核对。」 | warning |
| 超时/没回话 | 「连接超时」或「等待版本横幅超时（端口开着但没回 SSH 话）」 | `chip-warning`「超时」 + Error 原文；前者 hint「防火墙静默丢包或地址不可达」，后者 hint「端口开了但不是 sshd 在应答」 | warning |

- 进行中：按钮原位保宽（防布局跳动，operation panel 契约），文案「探测中…」+ `.live-pulse`（pulse 只挂进行中，N37② 在案）；同一行忙时其余行动作钮禁用（跨行的网络探测并行会互相搅结果，单飞锁学 `useAsyncAction`，但**锁粒度=行**：并发上限 1 只禁"再来一个"，不禁编辑/删除——与端口扫描"任务制"不同，这里是逐条短动作）。
- 取消：探测有 5s 级预算，给展开条上 [取消]（`.link-button` 第四档）；取消后展开条落「已取消」中性态。
- 逐行手动、不做批量（§10）。

## 6. 「部署公钥」：现场输一次密码、用完即弃（全界面最要紧的设计）

### 6.1 动作定性

这一步会：① 用密码**真实登录远端一次**（对端 sshd 日志留下成功记录；失败则留下 `Failed password`，可能触发 fail2ban——portscan 面板已有的提示义务在这里只重不轻）；② **改远端文件**：往 `~/.ssh/authorized_keys` 追加一行公钥。它比"试登录"更重（试登录只留记录，部署留下永久门），所以：**显式按钮、显式确认、口令防泄露三件套、全程可中止**。按钮用 `.btn-secondary` 档（它是"危险流程的入口"而不是"绿勾成功"，不用 `.btn-positive`——绿色档语义是确认/发送类动作完成态，误用会把风险动作染成安全色）。

### 6.2 流程状态机（模态内，一步不落账本）

```
入口(行钮) → [前置检查: 本机公钥在否/账本行完整否]
  ├─ 有公钥 → 口令步（输入+显式「显示」开关）
  │            → [确认步 useConfirm, tone=warning] → [执行中(不可重入)]
  │            → 结果四态(§6.5)：成功/失败都 → 立即销毁口令
  └─ 无公钥 → [生成分支：显式确认后才建钥] → 口令步（同上）
任意点 Esc/取消/遮罩 → 关模态、销毁口令、远端零动作
```

前置检查不过（地址空/行数据非法）：不开模态，直接把错误落回列表该行展开条（"先修账本，再谈部署"）。

### 6.3 口令字段处理（与 `SSHCheckPanel.vue` 明文形制的分道声明）

- `type="password"`；旁边**「显示」checkbox**（勾选期间临时转 text，取消勾选立即回掩码；默认恒掩码）。旧面板"明文便于核对粘贴多带的字符"的需求真实存在，但正确载体是**用户显式发起的临时显示**，不是默认泄露面——详见 §11.2。
- `autocomplete="off" spellcheck="false"`（家族在案）；**不得走 `usePrompt`/UiPromptDialog**——实读该对话框输入是 `type="text"`（UiPromptDialog.vue 68 行），口令进它等于明文。本模态是模块自建卡片（modal-card 家族），不新造全局组件。
- 生命周期即纪律：口令只存于该模态实例内存 ref；成功、失败、取消、Esc、遮罩、组件卸载**任一出口都先置空再走**；不写账本字段、不进结果对象、不进 `aria-live` 播报文本、不进任何"复制结果"输出、toast 不含口令（哪怕来自后端错误——后端红线：错误文本过 `redactSecret`，纪律源头在 sshauth.go 头注，§12-4）。
- 输入框配 `<label>`「一次性登录密码」；placeholder 用「仅本次使用，不会保存」。

### 6.4 确认步文案（`useConfirm`，`tone:'warning'`，逐字定稿）

> **title**：向 nas01 部署公钥？
> **details**：目标 `192.168.1.10:22` ／ 登录用户 `deploy` ／ 公钥 `C:\Users\…\.ssh\id_ed25519.pub`（指纹 `SHA256:…`，本机无公钥时此项显示「将新生成」）
> **description**：下一步输入的一次性密码只用于这次登录：不保存、不写入清单、不回显、关闭即销毁。登录成功后会向远端 `~/.ssh/authorized_keys` **追加**这一条公钥（已存在相同条目时跳过不重复写）。对端 sshd 日志会留下一条成功登录记录；若密码输错，会留下失败记录——装了 fail2ban 的主机连续失败可能被临时封禁本机 IP。
> **confirmLabel**：继续，输入密码

生成分支（本机无密钥对）在口令步**之前**插入独立确认（凭据文件生成是红线动作，一次都不许"顺手"）：

> 本机还没有 SSH 密钥对（`~/.ssh` 下没有 `id_ed25519.pub`）。生成密钥对会**新建**私钥与公钥两个文件：不带口令（passphrase）、**不覆盖任何既有文件**；公钥内容将显示给你核对。[生成并继续] [取消]

此条同时是对仓内旧事故（PLAN_REMAINING_WORK 292 行：会话擅自生成 `~/.ssh/hanxi_srv154` 未授权凭据）的制度化防重犯——生成本机凭据必须过一道显式确认，写进设计不靠记性。

### 6.5 结果四态（与测连通同一展开条语法；成功也不吹"以后都进得去"）

| 态 | chip | 文案 |
|---|---|---|
| 成功 | `chip-positive`「公钥已部署」 | 「远端 authorized_keys 已写入。建议核对下方指纹与你认知中这台机器的 host key 一致：<类型+指纹 mono>。本次登录未校验 known_hosts（与连通测试同一边界），对端换了机器你察觉不到——不一致请在远端删掉刚写入的行。」 |
| 密码被拒 | `chip-warning`「密码被拒绝」 | 「未写入任何内容。也可能是这台机器不接受密码登录（只允许密钥）——x/crypto/ssh 在 API 层面区分不了这两种（源头同款注记，§12-4 由部署 RPC 继承）。再试一次，或改用其他凭据入口到远端手工添加。」 |
| 连不上/超时 | `chip-danger`/`chip-warning` | 复用 §5.2 桶文案，加一句「部署未发生，远端无改动」 |
| 写入失败 | `chip-danger`「登录成功但写入失败」 | 「远端拒绝写 `~/.ssh/authorized_keys`（常见：目录权限 777、磁盘满、账号被限制）。登录记录已产生；公钥未生效。」 |

失败后「再试」保留表单其余字段、口令须重新输入（不缓存在途口令）。全程忙时该模态禁重复提交，按钮保宽。

## 7. 导出状态区：账本 ↔ `~/.ssh/hanxi.conf` 对账

### 7.1 路径与写盘位置的如实交代

导出目标显示**后端解析并回传的绝对路径**（Windows 现值形如 `C:\Users\<用户名>\.ssh\hanxi.conf`），UI 永不硬拼 `~`——路径来自 RPC（§12-3），显示用 `.mono` + `overflow-wrap:anywhere`。对账带底部常驻一行 `.hint-line`：

> 导出会写到你的**用户主目录**（不是 hanxi 安装/数据目录，不随 NAS 同步走）。它只管理 `hanxi.conf` 这一个文件：hanxi 写的归 hanxi 覆盖，你手写的别的 ssh 配置一概不碰。

### 7.2 状态语义表（对账带唯一状态位）

判据：后端持久化"上次导出时的账本指纹"（内容哈希，§12-3），比对=账本指纹 vs 上次导出指纹；文件存在性 stat；`Include` 检测。UI 不拿时间戳猜。

| 状态 | 条件 | 呈现 | 动作 |
|---|---|---|---|
| 从未导出 | 账本>0 行且文件不存在 | `chip-information`「账本还没导出给 ssh」 | [导出配置]（页头 `.btn-primary`）；副文案「现在 `ssh nas01` 还不认识这些别名」 |
| 一致 | 指纹相符且文件在 | `chip-positive`「已导出，与账本一致」 + mono 时间 | 无主钮（[重新导出] 降 `.btn-secondary`，多数时候没得点） |
| 待导出 | 账本已变（新增 n/修改 n/停用 n/删除 n，计数来自后端比对） | `chip-warning`「账本改了 n 处，还没导出」 + 摘要行「新增 1 · 修改 1 · 停用 1」 | [导出配置] `.btn-primary`——**账本一改，导出带成为全页唯一 CTA 位**，"改了没导出"绝不允许静默 |
| 外部改动 | 文件在、指纹不符、账本没变 | `chip-warning`「hanxi.conf 被外部改过」 | [重新导出] 触发 `useConfirm tone=danger`：「重新导出会用账本内容**整体覆盖** `C:\Users\…\hanxi.conf`，你在文件里手改的内容将丢失。确定？」——这是本区唯一的破坏性写，必须过确认 |
| 导出失败 | 写盘出错（权限/磁盘） | `banner-error`「导出失败：<后端原文>」 + [重试] | 保留上条状态语义（"上次成功 14:03"不消失） |
| Include 缺失 | 导出成功但 `~/.ssh/config` 无 Include 行 | `chip-warning`「导出成功，但 ssh 还不会读它：`~/.ssh/config` 里缺少 `Include hanxi.conf` 行」 | **默认只给指引文案**（教你自己加那一行 + 显示 config 路径）；"一键补写 Include"因为要碰**用户自己的** config 文件（个人资产，非 hanxi 派生物）列为刻意不做（§10），若机主改判要做，须独立 danger 确认 + 先说明备份去向，另立后端契约 |
| 停用行 | 账本有、导出无 | 行给 `chip-neutral`「已停用（不在导出配置中）」——停用与导出之间又隔一步，说明写在这 |

导出本身**免确认**（目标文件由 hanxi 专属持有、账本是唯一真相、无用户资产损失面），执行后 toast 回执 + 对账带即时翻「一致」；批量列表行内"待导出"微随动。

## 8. 窄窗与缩放行为（"刷新网卡"事故防重犯）

已知事故根因回顾：钮基座补 `white-space:nowrap` 后钮变宽，而 flex 容器缺 `flex-wrap` 把末颗顶出窗口；全局 `.btn-group` 已补 wrap，但全库仍登记 12 处 scoped 容器缺 wrap（PLAN_REMAINING_WORK 待办在册）。本模块条款：

1. **本模块所有钮容器优先挂全局 `.btn-group` 原子**（自带 `flex-wrap: wrap`）；确需 scoped 自定义容器（如行展开条里的结果+动作混排），`display:flex` 出现处必配 `flex-wrap:wrap`——写进本模块验收单（§13），并建议后续按既有提案补"flex 钮容器必含 wrap"的全局契约测试，本模块零新增欠账。
2. **档位表（主次分明，不发明新档）**：

| 位 | 钮 | 档 |
|---|---|---|
| 页头 | 导出配置 | `.btn .btn-primary`（36，蓝洗，全页唯一主钮档；密集行内同形不分档——四轮返工终态） |
| 页头 | 新增主机 | `.btn .btn-secondary`（36，`surface-soft` 底标准次级档） |
| 行内 | 测连通/部署公钥/编辑/删除 | `.btn .btn-secondary .btn-micro`（24） |
| 展开条/指引 | 再试、取消探测、查看路径说明 | `.link-button`（第四档文字链） |
| 模态 | 保存/继续/生成并继续 | `.btn .btn-primary`；取消/重试 `.btn .btn-secondary`；删除确认 `.btn .btn-danger` |

3. **降级顺序（越窄越先丢次要信息，主操作永不挤没）**：
   - ≤760px：列表 `.tbl` 转**行卡**（design-system 资源行契约：窄屏纵向组合而非挤压列）——第一行：启用+别名+密钥缺失 chip（密钥缺失是"要行动的状态"，窄窗优先级高于备注/用户）；第二行：`user@host:port` mono 合成一行；第三行：备注（有才显）；第四行：动作组 wrap 排；
   - 列隐藏序：备注 → 用户 → 端口（并入地址 mono `:` 原文）→（**别名与密钥状态永不移**）；
   - 页头：subtitle 先隐；再收 [新增主机] 文字→icon-only（AppIcon 注册表 `i:` 件，aria-label「新增主机」必备——禁散写 `<svg>`、禁 emoji 主图标；portscan 家族既有 emoji 不扩散到新模块）；**导出配置钮任何宽度保持文字形态**（状态载体词，icon 表达不了"待导出"）；
   - 460px 以下：模态转底部抽屉、页头两钮各占 50% 堆叠（ConfirmDialog/MsixOverview 460 先例）；对账带文案折行不截断。
4. **200% 缩放**：页面不横向滚动；长路径/地址在 `.table-container` 内自滚（宽表壳滚动契约）；文本子项 `min-width:0`、栅格列 `minmax(0,1fr)`（design-system 硬条款）；行最小高保持桌面 52px 档，粗指针环境 `pointer:coarse` 兜底 44px 由 base.css 全局承担，视图不复写。

## 9. 无障碍要点

- 键盘全程可达：列表动作、行展开条、对账带按钮全部 Tab 序；行卡折叠体用 `aria-expanded` 的 button 控制（家族 `.check-advanced` 先例）；Esc 关模态并把焦点**还给唤起钮**（清单在案）；模态焦点环走 `useDialogA11y` 单源（UiPromptDialog 先例），不手搓 trap。
- 每个输入有真实 `<label>`；错误文本 `aria-describedby` 绑字段 + `aria-invalid`；保存失败焦点落首错字段。
- 测连通/部署结果容器 `role="status"` + `aria-live="polite"`：只在"一次动作完成"时播报，进行中 pulse 纯视觉（checklist：live region 不追高频）。
- 启用 checkbox 有逐行 accessible name（「启用主机 nas01」）；密钥缺失、部署风险等状态全部**文本+图标双通道**，色仅冗余编码（禁只靠色、禁只靠变淡——stale 契约）。
- icon-only 降级钮（窄窗新增主机）：`aria-label` + `title` 同文；装饰 SVG `aria-hidden="true"`。
- 对比度不在本模块自证：一切色走全局 token 与原子，`buttonColorContract` 绿灯即契约面达成；口令「显示」开关勾选前后，label 文案不变，状态经 checkbox 自身可读出。

## 10. 刻意不做（及理由）

| 不做 | 理由 |
|---|---|
| 保存远端密码（"记住密码"） | 与「用完即弃」的动作定性直接冲突；DPAPI 虽在（模块自身配置加密面），给"用户远端机密码"开口子=把设计最硬的一条契约变成可选项，机主换机场景里存了密码的账本比缺钥匙的账本危险得多 |
| 批量测连通 / 一键部署全部 | 对第三方机器制造网络噪声，fail2ban 放大风险；与"每台机器单独确认"的部署纪律冲突。几十行的账本，逐行点不累 |
| 嵌终端 / 从 hanxi 里开会话 | 本模块管账本与对账，不是 SSH 客户端；WindTerm/Termora 托管线已覆盖终端需求 |
| known_hosts 管理 / 首次指纹信任流程 | 写 `~/.ssh/config`/`known_hosts` 是碰用户个人 ssh 资产（红线面），收益/风险不匹配；指纹只做展示与人工核对（§6.5） |

## 11. 与现有 `SSHCheckPanel.vue` 的关系（裁断）

> 由新视图 `SshKeysView.vue` 承载，`PortScanView` 的第三标签页随之撤销（且

> 作为**另一种成立的取舍**保留在案，不改写；下面 §11.1 及其证据表路径、:355 的
> 「本仓不可见」声明均属裁断前的旧盘陈述。
>
> 本节裁断里**被实施采纳的部分**：口令输入框改 `type="password"` + 显式「显示」勾选、

> **仍待机主裁**：卡内 h2 与页头 title 重名（实施会话判断属产品决定，未擅动）。

### 11.1 结论：面板留在 portscan「网络测试」第三标签页**不搬**；新模块自做行内版式，复用的是**后端 CheckSSH 能力**而非那个前端面板。

理由（逐条对事实）：

1. **心智模型不同**：SSHCheckPanel 是"自由探测仪"——host/port 手填、端口预设胶囊、可选试登录，面向任意一次性目标；新模块的测连通是"账本行动作"，输入全部来自行（用户还要先选行），结果落行展开条。搬过去等于把输入组+胶囊+试登录带进一个它们统统多余的面，再把可复用部分（结论区约二十行形制）拆成共享组件——skill Vue 映射条款明令"仅在复用或复杂度成理由时抽组件，不为一个页面造并行组件系统"。
2. **搬走即回归**：`PortScanView` 三标签结构（FACTS 在案：网络测试页=端口扫描/代理连通性/SSH 三页）会当场缺一角，`SSHCheckPanel.spec.ts` 钉死的行为特征全数作废重写——为设计省一笔复制而删另一个模块已验收能力，不做。
3. **"搬来的 CheckSSH"指后端 RPC**（任务书原话"复用搬来的 `CheckSSH`"）：banner 探测内核无论最终留在 `portscan` 包还是迁入新模块，前端只认绑定路径与结果模型；两边面板形制各归各模块目录（`components/portscan/` vs 未来 `components/sshkeys/`），符合 FACTS「路径跟模块 ID」纪律。
4. **凭据语义不同**：SSHCheckPanel 的密码路径是"试登录"（只留日志记录）；新模块的密码路径是"部署公钥"（留记录**且改远端文件**）。同壳承载两种风险级不同的凭据动作，只会在 props 分支里长出"此处隐藏彼处显示"的怪物壳。

### 11.2 口令明文旧理由在本场景不成立（及为何不同）

`SSHCheckPanel.vue` 68 行密码 `type="text"`，理由记在 `SSHCheckPanel.spec.ts` 76–77 行：测试场景要能核对粘贴来的密码有没有多带字符。该理由在部署公钥场景**被三条事实压过**：

- **泄露后果的量级不同**：试登录输错最多一条 Failed password；部署的口令是"往远端 authorized_keys 写行"的那把门钥匙，一旦被旁观（共享工位/远程演示/录制环境——本模块恰是"跟人到处用"的界面，这些场合使用频率高于 portscan 调试页），泄露的不是这一次输入，而是远端账号本身。
- **暴露时长不同**：部署流程含前置检查、生成确认、口令输入、风险确认四拍，从输入到执行存在客观间隔，明文意味着这整段时间持续可见；试登录是输入即点击即销毁。
- **原始需求有更好载体**："核对粘贴字符"的真实需求由默认掩码 + **显式「显示」勾选**完整满足（§6.3），且显示的决定权、时长都归用户——明文常显是把选择成本转嫁给所有不核对的场合。

顺带登记（不阻塞本模块、不越权改动）：portscan 自家那枚明文是否同样降为"掩码+临时显示"，归 portscan 所有权线裁决；若改，需同步 `SSHCheckPanel.spec.ts`——其注释已把"明文"当作可断言特征钉死（76 行注释：遮挡类型不再是特征即因此而来）。
