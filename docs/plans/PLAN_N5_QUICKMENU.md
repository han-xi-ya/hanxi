## 1. 改进批次（按痛点收益排序）

### B1 触发键可配置（中键/侧键直按）——"不好用"最大根源的止血
- mousetrap 扩展：`WH_MOUSE_LL` 已收 XBUTTON1/2（侧键 vkCode 5/6）与中键
  （vkCode 4）事件；新增触发模式：右键长按（现状保留）/ **中键直按** /
  **侧键直按**（后两者零长按等待、与右键应用手势彻底互不干扰）；
- 中/侧键直按的吞放策略与右键不同：直按即吞（不回放短按），因为中键在多数
  应用是"滚动/新窗口"高价值键——**默认不启用，配置页明示冲突代价**；
- 配置面：quickmenu 设置页触发模式下拉 + 长按时长滑杆（300–800ms，仅右键
  长按模式有效）合并成一组"触发"设置；后端 Config + bindings 重生成。

### B2 应用排除清单（per-app 白话版）
- 判据：轮盘唤出瞬间取前台窗口进程名（GetForegroundWindow→GetWindowThread
  ProcessId→QueryFullProcessImageName，均为 platform 已有能力的薄封装）；
- 命中清单 → 本次唤出抑制并**完整回放右键**（与短按回放同一通道，零吞键）；
- 配置形态：模块页文本框（分号分隔进程名，不区分大小写）+ 开箱默认宁缺毋滥：
  只放 explorer.exe（右键拖拽重灾区），winword/wps 等候选由机主自加；
- 刻意不做 StarPie 的"按应用动作集"（per-app 换扇区内容）：托盘条目本身
  已是全局共享模型，分应用配置把数据模型复杂一个量级、自用场景收益不明。

### B3 几何同源锁（欠账收口，测试级）
- 快照文件一份（`wheel_geometry.json` 或 go/ts 内联常量表，实施时定形）：
  Go 测试断言 service 常量 == 快照，前端 spec 断言 `WHEEL` == 快照——数值变更
  必须「源两处 + 快照一处」同步，漏改即双红；
- 不做运行时下发（前端读 Go 注入）：常量在编译期对齐的简单性优先，弹窗
  几何历史上就是"定稿值"（注释自述），非动态参数。

### B4 观感微调候选（真机验收时顺带定）
- 长按触发期无预反馈 → 候选：钩子按下 200ms 后在光标旁画"填充进度微点"
  （复用现有透明窗需扩窗，收益小则砍）；默认不做，验收时机主要是槽点再立子项。

## 2. 不做清单（纠偏项，写明理由防"照抄回潮"）

- ✗ "移动即出盘"替换拖拽放行（保资源管理器右拖文件，真机教训有案可查）；
- ✗ 扇区数 4/8/12 手动槽（自适应切分已是更优解）；
- ✗ per-app 动作集（B2 只做"抑制"不做"换内容"，理由见 B2）；
- ✗ 二级环再加深（帽带一层已覆盖分组需求，StarPie 也是双环封顶）。
