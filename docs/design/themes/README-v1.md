## 1. 现状评估（青壳基线的问题）

现有主题：主色青绿 `#0f8b8d`，中性面统一青灰调（design-system.md 标定）。量化短板：

| 配对 | 现状 | 问题 |
|---|---:|---|
| 浅·白字 / 主按钮 `#0f8b8d` | 4.12:1 | **低于 AA 4.5**，小字号按钮文本吃力 |
| 浅·弱注记 `#8a9aa0` / 面板 | 2.91:1 | 低于 3:1 图形门槛，浅底几乎不可读 |
| 色相覆盖 | 仅青绿一族 | 所有界面一个味道；无中性/暖色/冷暖分化选项 |

深色标定本身健康（6.8–7.5:1），问题集中在浅色。

## 2. 设计原则（除曜石外共同遵守；曜石为无障碍向，状态色也整体强化）

1. **状态色跨色板恒定**：positive/information/warning/danger 双模式数值不随色板变——运维用户对"红=错误"的记忆必须稳定；色板只换主色与中性面。
2. **中性面随色相轻染**：page/soft/hover/border/text 按色板色相做 6–12% 低饱和染色（延续现状"青灰"手法），选中行 = 主色 12% 混白。
3. **浅深独立标定，非反色**：深色提亮有彩前景（design-system.md §Theme calibration），深主色的按钮前景改用深色字（对比 7:1 上下）。
4. **对比度基线**：正文 ≥4.5（实际全部 ≥14）、辅助字 ≥4.5、弱注记 ≥3、主按钮字 ≥4.5、主色链接字 ≥4.5、选中行文字 ≥4.5。
5. **光晕/焦点环/阴影随主色染色**，alpha 沿用现状（soft 10%/13%、glow 0.18/0.2、focus 0.24→0.26/0.28）。
6. 终端色板（`--terminal-*` / `--ansi-*`）固定深底，永不随色板反相（既有决策，不动）。

## 4. 落地方案建议（确认色板后再实施）

现 `tokens.css` 注释假设"新主题 = 新增 `[data-theme='xxx']` 块"，即单轴枚举；10 色板 × 2 模式 = 20 块会组合爆炸，且"跟随系统"语义纠缠。**建议双轴**：

- `data-theme="light|dark|..."` 保留为**模式轴**（现状零改动：状态色、遮罩、深模式阴影、终端块继续住这里）；
- 新增 `data-accent="teal|cobalt|graphite|moss|rust|plum|azure|rose|ink|onyx"` **色板轴**，每块只覆写主色组 + 染色中性面 + 光晕/焦点/浅影（曜石额外覆写状态色）——即 preview.html 里的 20 个块，原样可粘；
- 后端 `AppSettings` 增 `Accent string` 字段（与闲置已久的 `Theme` 同款持久化路径，便携版随 `hanxidata/` 迁移）；`useTheme.ts` 拆为 `useTheme`（模式）+ `useAccent`（色板），或一个 composable 管两个属性——仍是主题唯一读写入口；
- 设置页主题切换器加一排色板圆点；DWM 标题栏同步只依赖模式轴，不受影响；
- 默认值建议：出厂默认保持 `teal`（品牌连续），首屏引导里把 `cobalt` 作为主推可选项——是否改默认属产品决策，见后。

**需要拍板的三个问题**：① 哪几套进最终清单（5 全要 / 砍到 3）；② 默认色板是否从青壳改弦更张；③ 浅色基线的两处对比度硬伤（主按钮 4.12、弱注记 2.91）是否不等新色板、先在 `teal` 上热修。
