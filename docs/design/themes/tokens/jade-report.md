# jade · 青瓷 单套深化报告（v2.1）

> 对象：`docs/design/themes/preview.html` 中 `[data-accent="jade"]` 两块（即 `gen-palettes-v2.mjs` 参数化产出，已逐值验证二者一致）。
> 产出：[`jade.css`](jade.css)（浅色 19 枚 / 深色 17 枚覆写，变量名集合与 sky 块完全对齐）+ 本报告 + 微型自检页 [`jade-check.html`](jade-check.html)。
> 口径：node 实算（`lib.mjs` 与 gen-palettes-v2.mjs 同一套 `oklchToLin`/gamma/sRGB 裁切，另实现反向 hex→OKLCH），对比度为 WCAG 相对亮度比。

## 0. 结论先行

- preview 版 jade 有 **5 处真实缺陷**（浅色 3 + 深色 2）和 **1 个族级语义冲突**（主色贴 positive 绿族），本稿全部修复/缓解：
  1. 浅 `panel→soft` 台阶 ΔL 仅 0.019（族纪律 ≥0.02）→ soft `.981→.978`，现 0.022 ✓；
  2. 浅 辅助字/选中行 3.92 < 4.5（表内 mono 列常态组合）→ muted `.52→.485`，现 4.59 ✓；
  3. 浅 弱注记/页面 2.92 < 3.0 → subtle `.65→.63`，现 3.16 ✓；
  4. 深 辅助字/选中行 3.65 < 4.5 → selected `.440→.414` + muted `.77→.80`，现 4.52 ✓；
  5. 深 主色/选中行 4.08 < 4.5（侧栏选中项文字色）→ 同上修复，现 4.59 ✓；
  6. 主色 vs positive 色相距离过近（浅 25.6°、深仅 17.6°）→ 两模式主色推冷回品牌正色相，现 **33.4° / 31.5°** ✓。
- 深色盘 **29 项配对全过、零例外**；浅色盘色板职权内 **全过**，仅剩 3 项 ✗ 属跨色板常量层 `--state-*`（族纪律禁改，见 §7 风险 1，需全族议题）。
- 品牌连续度反而比 preview 版更高：新主色与现状默认 teal 的 OKLCH 色相差仅 **0.8°（浅）/ 1°（深）**，preview 版是 9°/13°——"一眼同族但更高级"由"同色相、浅加深半档 / 深加亮半档"承担。

## 4. 审查重点① —— 主色 vs positive（祖母绿）色距分析

"运行中 chip（positive 字 + 软底）与主按钮同屏"是本盘最大语义风险。度量取 OKLCH 双距离（色相弧差 + 明度差）与直角 ΔE：

| 组合 | 旧 Δh / ΔL / ΔE | 新 Δh / ΔL / ΔE | 判定 |
|---|---|---|---|
| 浅 主色 vs `#08875d` | 25.6° / .073 / .092 | **33.4° / .083 / .107** | 旧版两个"深绿"并排易混；新主色转墨青后色相差 >30°，且明度差拉大到 .083（主按钮更深、chip 字更浅） |
| 深 主色 vs `#47c792` | **17.6° / .045 / .067** | **31.5° / .049 / .087** | 旧版是全案最危险相邻（亮翡翠 vs 亮祖母绿）；Δh 翻倍后回到品牌 teal 自己的安全位 |
| 参照：品牌 `#42b7b4` vs `#47c792` | 30.5° / .031 / .078 | — | preview 版比现状品牌还近 13°；新方案等于"把品牌的安全色相带上来的亮度" |

与品牌默认 teal 的连续性（族审查要求"一眼同族但更高级"）：

| 模式 | 品牌默认 | 深化后 | 关系 |
|---|---|---|---|
| 浅 | `#0f8b8d` L.579 C.096 **h197** | `#006869` L.469 C.080 **h196** | 色相差 0.8°，明度深 .11 → "深潭化"的品牌进化（preview 版偏到 h188，差 9°） |
| 深 | `#42b7b4` L.714 C.103 **h193** | `#5dd1cf` L.794 C.105 **h194** | 色相差 1.0°，明度提 .08 → 更亮更透的"夜釉"（preview 版 h180，差 13°） |

与 information 蓝无新增冲突（浅 Δh 67°、深 Δh 67.4°）。主按钮底 vs 成功软底相邻：浅 `#006869`/`#e2f4ec` = 5.51 以上、深 `#5dd1cf`/`#0f2e24` ≈ 8 级差，大面积相邻时也无粘连。

残余：深模式 ΔE .087 仍 <0.1（亮色+深字策略下 L 只能取 .79 一带，明度距离被锁死，全靠色相），见 §7 风险 3。

## 5. 审查重点② —— 深模式 selected `#155e5e` 强染色行上的四枚状态 chip

状态色及其软底为跨色板常量（不动），可调的只有行表面。旧行 L .440 上新行 L .414：

| chip（深） | 字/软底（恒定） | 软底/行 分离度 旧→新 | 软底ΔL vs 行 旧→新 | 软底Δh vs 行 旧→新 |
|---|---|---|---|---|
| 成功 `#0f2e24` | 6.86 ✓ | 1.95 → 1.74 | .166 → .140 | 25.7° → 26.8° |
| 信息 `#16233c` | 6.38 ✓ | 2.09 → 1.87 | .182 → .156 | 67.5° → 66.4° |
| 警告 `#33260f` | 7.50 ✓ | 1.96 → 1.76 | .162 → .136 | 115° → 116.1° |
| 危险 `#3a1a1a` | 6.14 ✓ | 2.08 → 1.87 | .176 → .150 | 173.9° → 175° |

结论：四枚 chip 在旧行 `#155e5e` 上本就**不发闷**（字/软底 ≥6.1，底/行 ≥1.9、ΔL≥.16），真正糊的是**行上的辅助字（3.65）与主色文字（4.08）**。行内收半档后 chip 分离度仍 ≥1.74 / ΔL ≥.136，肉眼仍是清楚的"暗药丸浮在染色行上"；同时辅助字 4.52、主色字 4.59 转绿。浅模式对称组合（软底/行 1.18–1.23、ΔL .062–.074）本来分离度就低，靠 colored 文字与 27°–177° 色相辨读，行未改动，风险记 §7-4。

## 7. 遗留风险与上报

1. **（跨族，需议题）浅模式常量层三枚状态字/软底不达 4**：成功 3.97、警告 3.56、危险 3.74（信息 4.47 ✓）。这是 `--state-*` 浅色现状值的问题，teal/sky/iris/jade 全族同病，族纪律禁止本盘覆写，故如实亮红不私调。建议单列"浅色状态字深一档"的全族标定（已顺手实算备选，软底不动）：成功 `#08875d→#067d4d`（L .552→.52，3.97→4.54）；警告 `#b66f08→#955e00`（L .606→.53，3.56→4.83）；危险 `#d64545→#b33736`（L .597→.52，3.74→5.10，此枚会明显偏沉，需配合把 `#fbe9e9` 提亮才两全，权衡留给该议题）。
2. **弱注记在选中行上不达 3**（浅 2.50 / 深 2.42）：preview mock 无此组合（行内只用 muted），但落地若有视图在选中行放 `--color-text-subtle`，需局部加粗/升档，或届时在组件层规避。
3. **深模式 主色↔positive ΔE .087 仍偏小**：受"亮主色 + 深字"族策略约束（L 不能太低否则深字不达、不能太高否则失重），明度距离封顶在 .05 上下，31.5° 冷色相差是主要防线。若目测评审仍觉并排 chip/按钮不够分，仅剩两条路：主色再偏蓝（伤"青瓷"命名）或放弃深字策略（违反族原则 3），均不建议；备选缓解是运行时保持 chip 必带软底 + 文案/图标冗余（design-system 本有此规）。
4. **浅模式四枚 chip 软底与强染色行分离仅 1.18–1.23（ΔL≈.065）**：preview 版即如此，行未改动不算回归；选中行同时挂 chip 的场景以深色态为主，浅色态建议保留 chip 彩色文字即可辨。
5. **同一台阶缺口存在于 sky（soft .982→ΔL .018）**：本稿的 soft 修法（L→.978）可直接平移到 sky；iris 恰好 .020 压线。属提案稿族级一致性问题，留给汇总评审。
6. **浅主色为 sRGB 裁切值**：spec `oklch(.47,.11,196)` 在深 L 高 C 区被裁到实测 C .080——"墨青"的沉是色域物理上限，非疏漏；若日后回填 `gen-palettes-v2.mjs` 参数，请以本稿 hex 为准回推，别拿未裁参数重算。
7. 本稿未动 `--terminal-*`/`--ansi-*`/字号/半径/动效；`#63d3d1`（ansi-14，现状品牌衍生亮青）与深主色 `#5dd1cf` 极近——终端永不反相、语境隔离，无冲突，但若未来重标终端色板可顺手同源。
