## 3. 感知台阶核对（OKLCH ΔL）

| 链路 | page | panel | soft | hover | selected |
|---|---:|---:|---:|---:|---:|
| 浅 L | .965 | 1.000 | .979 | .941 | .885 |
| 浅 ΔL（逐级） | → +.035 | → −.021 | → −.039 | → −.056 | 方向：panel 最亮、soft 次之、hover→sel 递深 ✓，各级 ≥.02 ✓ |
| 深 L | .210 | .258 | .304 | .360 | **.401** |
| 深 ΔL（逐级） | → +.048 | → +.046 | → +.056 | → +.041 | 单调递亮 ✓，各级 ≥.02 ✓ |

- 浅色 panel→soft 的 |ΔL|=.021，贴近下限但合格（与 preview 相同，未改动故无回归）。
- 深色选中行由 .435 压至 .401 后，hover→sel 台阶仍有 ΔL .041 / ΔE .06，hover 与选中可区分；
  且 chip 软底（L .259–.282）与选中行的 ΔL 从旧 −.151～−.176 变为 −.123～−.143、ΔE ≥.15，
  "深色选中行上一片紫灰糊住"的风险随选中行整体压暗而**降低**（chip 相对更沉、行底色相对更净）。

## 4. iris 专属审查结论

**① 浅：薰衣草紫面 × 高彩鸢尾——与 information 蓝 / warning 黄 chip 的竞争。**
- 真竞争点是主色本身而非面：旧 `#5645d5` 与 information `#2563eb` 仅隔 18°（ΔE .081），
  链接字与小号 chip 字同屏近亲；旋到 `#6741ca` 后 27°/ΔE .110，配合 chip 自带软底，可稳定分辨。
- 中性面组（h 300，C ≤.05）不转 hue：实算 chip 软底 vs 浅选中行 ΔL +.064～+.076、ΔE .08～.11，
  vs 面板/页面 ΔL +.02～.07——软底 chip 始终比紫面**更亮更灰**，未出现同彩度抢戏；
  warning 黄（h≈85）与紫面是互补对（ΔE .11 最大），反而最醒目。故动用"降彩/转 hue"许可为不必要，选中行维持 C .05 保住 README 卖点"三套里个性最强"。

**② 深：`#584677` 选中行上四类状态 chip。**
- 四枚 chip 软底均为不可见的深暗底（L .259–.282），与选中行 L 差 ≥.12、ΔE ≥.15，"糊成一片"不成立；
  chip 字/自身软底 6.14–7.50 全过。
- 真正翻车的是 preview mock 里同一行的**主色文字**（nav.on / badge-newest 真实用法）：旧值 3.70 ✗。
  通过"选中行压暗 + 主色提亮"双动作为其让出 luminance（4.58 ✓），未靠砍选中行彩度作弊。
- 无软底、直接落在选中行的状态字（如列表彩色圆点旁的着色数值）：深 `inf` 3.85、`dgr` 3.71 仍 <4.5——
  属用法问题非色板问题，见 §5-R3。

**③ 主色与 danger 的色相距离。**
- 浅：`#6741ca` vs `#d64545` hueΔ 94.6°、ΔE .30——远超误认阈值，安全。
- 深：`#bba9fa` vs `#ff7974` hueΔ 90.3°——安全。紫↔红分处色轮两端，主色旋转不侵蚀此项。

## 5. 遗留风险与如实申报

- **R1（家族冻结债，iris 无法也不应修）**：任务底线要求"四类状态字/状态软底 ≥4"，但浅模式
  tokens.css 现行冻结值实算 **positive 3.97 / warning 3.56 / danger 3.74 不达标**（information 4.47 过）。
  此为 sky/jade/teal 全族同值共债，preview.html 审计区同样只以"AA 大字"徽章放行；iris 按纪律未覆写。
  **建议**：家族层立项把浅 `--state-positive/warning/danger` 下压明度（如 warning → `#a2630a` 一档）
  或软底提亮，另行全族复算，勿由各色板私改。
- **R2（浅模式参考项不达，用法纪律）**：浅选中行上 辅助字 3.87、弱注记 2.27（家族通病，sky 同量级）。
  淡紫强染色底与"选中行只放正文+主色标识"是设计意图一致：**选中行内禁用 muted/subtle 小字**，
  需要时改用 `--color-text`。深模式经本次压暗后 muted 4.55 转正、subtle 2.68 仍 <3，同纪律。
- **R3（状态字直落选中行）**：浅 2.78–3.61、深 3.57–4.81（详见临时脚本输出）——状态语义在选中行上
  必须走 chip 软底形态（现有 `.chip` 模式即是），禁止裸着色字。
- **R4（深 border↔hover ΔE .005）**：`#413b4c` 与 `#3f3a4b` 几乎同值，hover 行的边框融合——
  preview 各深色色板共有的既成模式（hover 底本就设计为无边高亮），未单改 iris 以免破坏族内一致，记录备考。
- **R5（感知主观项）**：`#6741ca` 比 `#5645d5` 更"紫"更少"蓝"，Arc 气质增强、微软系蓝感减弱；
  README 若定稿需同步更新对比摘要表（按钮字浅 6.59 / 深 7.98，主链接浅 6.59 / 深 7.61）。
- 未触碰：终端/字号/半径/动效等非色 token、`--state-*`、`color-scheme`、`--overlay-mask`、`--shadow-drawer`。

## 6. 复算方式

`iris.css` 的色值全部由 OKLCH 参数生成（浅主色 `oklch(.5 .2 290)`、浅 hover `oklch(.43 .19 290)`、
深主色 `oklch(.78 .115 294)`、深 hover `oklch(.82 .1 294)`、深选中 `oklch(.40 .075 300)`），
沿用 `gen-palettes-v2.mjs` 同一色域收缩映射；若族级参数（hN=300、面台阶表）后续统一调整，
按 §1 的旧→新映射重跑即可，全部硬底线在 §2/§3 表内留有 ≥.1（对比度）或 ≥.02（ΔL）余量的项已注明。
